# Heuristic Evaluation

Expert review (discount usability method), not user testing. This is one evaluator's pass, meant to sit alongside the designer's own independent review, not replace it.

## Optional context

If the user gives you specific tasks, JTBD scenarios, or user goals for the screen, evaluate with those in mind and reference them in "why it matters." If they don't, just evaluate the screen on its own merits, don't invent scenarios to tag issues against.

## Nielsen's 10 heuristics (reference)

1. Visibility of system status
2. Match between system and the real world
3. User control and freedom
4. Consistency and standards
5. Error prevention
6. Recognition rather than recall
7. Flexibility and efficiency of use
8. Aesthetic and minimalist design
9. Help users recognize, diagnose, and recover from errors
10. Help and documentation

## Severity rubric

- **High** — would block task completion, or cause a costly/high-stakes mistake. Real risk of the user failing the task or a downstream error.
- **Medium** — causes hesitation, confusion, or an extra step, but the user recovers without real damage.
- **Low** — minor friction
